# 读序与自包含

> 这份讲**怎么读、依赖什么、怎么接**，不改变任何元件源码。

---

## 1 · 先读哪一段（外部参考与提示词）

源项目里躺着一批外部提示词与风格包（约 703 份 `<direction>/<structure>/Banned` 三段式）。
教训是：**每次"学"都直奔可数的 `structure` 与 `Banned`，把第一行意图丢掉。**

正确读序：

```
<direction>  →  <structure>  →  Banned
   意图           可数结构       禁项
 （先读并      （再看）      （最后）
  一句话复述）
```

| 段 | 内容 | 为什么容易先读它 |
|---|---|---|
| `<direction>` | 一句装一整条形变链，中间过渡要自己补 | **要理解意图，最费力** |
| `<structure>` | 24 beats 之类可数结构 | 可数、可验、能填格子 |
| `Banned` | 禁项清单 | 最像「标准」，最好交差 |

> 一句可复用的判词：**「一形流动成另一形」不是「让什么东西进场」**。
> 把过程压成名词、把关系压成实体，是最省力的合规解，也是画面死掉的起点。
> 详见 `vibe-world-deduction/library-bridge/references/04_喂样式不喂流程.md`。

## 2 · 四个元件的自包含程度

| 元件 | 依赖 | 能否单独引 |
|---|---|---|
| `depth2d.js` | 无 | ✅ 完全独立（纯函数） |
| `bloom.js` | 无（自带确定性伪随机 `B.rnd(seed)`） | ✅ 可单独引；需要舞台坐标时自己建坐标系 |
| `face.js` | 挂 `window.FX` | ✅ 可单独引；表情要挂所属变换组 |
| `figure-parts.js` | 与 `bloom.js` 共用 `120×240` 骨架约定 | ⚠️ 建议与 `bloom.js` 一起引 |

**未包含**：`gsap.min.js`（第三方，许可另计）、各 `*.css`、最小样本 `index.html`、
`stage.js` / `forms.js` / `elements.js`。需要时回源库取。

> 若要用 GSAP 驱动，请自行引入并**自己承担时序**；元件本身不持有 `t`。

## 3 · 接入四式（对应 `library-bridge`）

| 式 | 在这里怎么用 |
|---|---|
| **A 直接调真元件** | 引 `assets/*.js`，按选型表取函数 |
| **B 只取造形不搬框架** | 源库是 SVG、本项目是 Canvas 2D 时，只抄形状与明暗逻辑 |
| **C 参数分化** | 多个同类元件加确定性分化字段（层级／簇数／倾斜／色阶），**不用 `Math.random`** |
| **D 只读参考** | 外部提示词／44 套模板：只带一句能落地的话回项目 |

## 4 · 两条最容易破的规矩

1. **`act` 与 `e` 成对**：上肢补间只给 `act` 会让肘部绕成整圈。
2. **子元件挂进所属坐标系**：眼睛／眼镜／局部肢体画在屏幕绝对坐标，机位一动就漂。
   判断标准不是「它看起来在哪」，是「**它属于谁的坐标系**」。

## 5 · 镜像与源库的关系

- 本仓库是**可发布镜像**：四个 JS 从源库复制，注释里的源项目机器路径已泛化。
- **源工程一字不动**：发布镜像不修改原库；要修元件请回源库，再同步镜像。
- 元件头部保留了来源说明与项目内片名（仅注释溯源，非运行依赖、非元件命名）。
- 源库仍在长；每次同步请记版本号与日期（见根目录 `README.md §迭代` 的 `SYNC.md` 待办）。

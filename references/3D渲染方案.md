# 3D 渲染方案 · Three.js 无头抽帧

> 本目录 `3d/` 收录一套**真 3D** 渲染管线：Three.js 场景 → 无头 Chrome → 逐帧截图 → ffmpeg 合成 MP4。
> 它与仓库根目录 `assets/` 里的 Canvas 2D 伪 3D 元件**是两套不同东西**（见文末对比）。

---

## 一、两种模式（同一套管线切换）

渲染后端由**无头 Chrome 的 GL 参数**决定，本仓库 `render.mjs` 用环境变量 `RENDER_GL` 切换：

| 模式 | 设置 | Chrome 关键参数 | 实测速度（1080×1920） |
|---|---|---|---|
| **方案A · SwiftShader 软件渲染** | `RENDER_GL` 不设或 `=swiftshader` | `--enable-unsafe-swiftshader --use-angle=swiftshader` | **1.45 帧/秒** |
| **方案B · 硬件 GPU 加速** | `RENDER_GL=gpu` | `--use-angle=gl` | 数倍提升（取决于本机 GPU） |

> **本机实情**：本机 GPU 为 Intel UHD，无头会话不保证硬件 WebGL 加速，
> 因此 **SwiftShader 软件渲染才是主路径**（不是"兜底"）。排期一律按 1.45 fps 的慢速算。
> 这是 `3D动画制作规范.md §6` 的实测结论：**3 秒 demo（90 帧）≈ 1 分钟，8220 帧正片 ≈ 1.9 小时**。

### 取图方式也影响速度（与 2D/3D 无关）

瓶颈不在"是不是 3D"，而在"怎么把每帧取出来"。同一套管线，换取图方式立刻提速：

| 取图方式 | 实测速度 | 如何开启 |
|---|---|---|
| `page.screenshot()` → PNG | 1.45 帧/秒（3D）/ 1.18（2D） | 默认 `CAPTURE=png` |
| `canvas.toDataURL('image/jpeg')` | ≈ 6.23 帧/秒（2D 实测，3D 按比例推 ≈ 4~5 倍） | `CAPTURE=jpeg` |

> 决策提示：**机位推拉仍然优先走 2D 伪 3D 元件**——理由是「准入三问不过」，
> 不是"3D 太慢"。真要 3D 时，正确的省钱做法是**换取图方式**，不是"为了快而选 2D"。

## 二、目录内容

```
3d/
├── scene.html        ← Three.js 场景（多面体 + 线框 + 粒子星云 + 辉光后处理）
│                      暴露 window.__render(i, total) 供无头脚本逐帧驱动
├── render.mjs        ← 无头抽帧脚本：内建静态服务 + puppeteer-core 驱动 chrome
├── encode.mjs        ← frames/*.png → out/three_anim.mp4（复用 ffmpeg）
├── package.json      ← 依赖：three、puppeteer-core
└── run-render.ps1    ← Windows 一键包装器
```

`scene.html` 用 importmap 从本地 `node_modules/three` 加载模块；
`render.mjs` 起一个本地 HTTP 服务（`127.0.0.1:8731`）喂给它。

## 三、运行步骤

```bash
cd 3d
npm install                 # 装 three + puppeteer-core

# 必要环境变量
export REMOTION_CHROME_PATH="/path/to/chrome-headless-shell"   # 指向该目录
export FFMPEG_PATH="/path/to/ffmpeg"                          # 可选，缺省取 PATH

# 方案A：软件渲染（默认）
node render.mjs
# 方案B：硬件 GPU
RENDER_GL=gpu node render.mjs
# 提速取图
CAPTURE=jpeg node render.mjs

# 合成视频
node encode.mjs
```

> **脱敏说明**：原始管线写死了 `F:/workbuddy_pro/...` 绝对路径；
> 本仓库版本全部改为**相对路径 + 环境变量**（`THREE_DIR` / `REMOTION_CHROME_PATH` /
> `FFMPEG_PATH` / `RENDER_GL` / `CAPTURE`），可直接 clone 后在任意机器跑。

## 四、与 `assets/` 伪 3D 元件的区别

| | `assets/` 伪 3D 元件 | `3d/` 真 3D 管线 |
|---|---|---|
| 技术 | 纯 Canvas 2D，无 WebGL | Three.js + WebGL |
| 立体感来源 | z 只用于排序/缩放/配色 | 真实几何 + 相机 + 光照 + 法线 |
| 是否真 3D | 否（招数累加 ≠ 升维） | 是 |
| 产出 | JS 函数，供网页/动画调用 | 离线渲染的 PNG 序列 → MP4 |
| 速度 | 即时 | 慢（1.45 fps 软件渲染） |
| 用途 | 角色/表情/肢体/视差 | 宇宙、粒子、产品环拍等需要真实体积的场景 |

一句话：**伪 3D 解决"平面上的东西看起来立体"，真 3D 解决"真的有个三维物体在转"。**
两者按「准入三问」择一，不互相替代。

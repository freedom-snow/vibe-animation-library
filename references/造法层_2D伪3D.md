# 造法层 · 2D 造 3D 观感（D2.* 摘要）

> 摘要自源库 `2D伪3D造法/README.md` 与 `assets/depth2d.js` 头部。
> **只收已核实的 A–F 六族；G／H 两族见源库 `造法卡.md`，本文件不臆造。**
> 元件本体在 [`../assets/depth2d.js`](../assets/depth2d.js)。

---

## 0 · 这一层补的是什么

三支自研库管「人怎么动／东西怎么聚散／画面里有什么」，
本库管第四件事：**画面有没有体积／纵深**。

| | |
|---|---|
| 技术形态 | 纯 Canvas 2D；`z` 只用于排序／缩放／配色，**丢弃 z 只画 x/y** |
| 不是 | WebGL、法线、光照点积、真 3D 模型 |
| 性质 | **造法层**，不是升维；招数累加不构成上 THREE 的理由 |

> 立体感是「**算出的深度**」，不是模型自带的。

## 1 · A–F 六族（已核实）

| 族 | 想做的画面 | 主要函数 |
|---|---|---|
| **A 圆头笔触体积** | 一个圆润的立体物件在转（盒子／球体／装置） | `D2.rotate3` · `transform` · `painterSort` · `drawRoundPath` · `faceColor` · `arcHandles` |
| **B 正交 + z 灰度雾** | 最省事地给线框／几何体加深度 | `D2.zFog` · `ortho` |
| **C 射线墙高** | 走廊／穿墙推进／一排墙由近及远 | `D2.planeDistance` · `wallHeight` · `fisheye` · `texColumn` |
| **D 定点 DDA + 方向选帧** | 整数数学做 2.5D、物件按视角换朝向 | `D2.toFpx` · `fromFpx` · `idiv` · `dirFrame` · `viewDir` |
| **E 序列帧 seek** | 产品环拍旋转，不写任何 3D 数学 | `D2.seqFrame` · `framesDelta` |
| **F 分层深度** | 单图切前／中／后景做视差 | `D2.depthToZ` · `focalPx` · `project` · `layerTransform` · `depthBands` · `depthThresholds` |

> **G／H**：源库造法卡共 A–H 八族，本摘要未展开后两族；
> 别根据族名猜函数名，用之前回源库核对。

## 2 · 三条不可破的库规（摘自 `depth2d.js` 头部）

1. **命名中性**：只用几何／物理名，不出现任何项目专名、角色名。
2. **元件只造形，不排时序**：没有一个函数持有 `t`、启动计时器或注册 `rAF`；
   时间一律由调用方以参数传入，返回值只依赖参数（**可乱序逐帧 seek**）。
3. **确定性**：禁 `Math.random` / `Date.now` / `performance.now` / `rAF` / 跨帧可变状态。

> 第 4 条「源工程一字不动」也写在头部：本文件是新写的接口化实现，
> 不改变被抽取的那些外部引擎里的任何源文件。

## 3 · 与「确定性五禁」的关系

`film-qa/references/02_确定性自检.md` 说：逐帧独立求值时，
全局 PRNG 状态依赖调用顺序会串帧；正解是**固定种子 + `t` 参与相位**的无状态做法。

`D2.*` 的做法更彻底：**完全没有随机，全是纯函数**。
需要随机分布（星点、碎屑、粒子）时由调用方给固定种子，元件不持有状态。

> 所以它能直接用于 `frame(t)` 范式：
> 同 `t` 必画同图，且可乱序重绘。

## 4 · 自检口径

源库记有「确定性自检 8/8」。本镜像未重跑该自检（需要源库的测试脚本），
所以这里**不宣称 8/8**，只说明设计前提。
> 要复用，请自行跑一遍：同参数连续调用两次结果全等；改变参数时只变对应输出。

## 5 · 用之前问两句

1. 我要的是**体积感**，还是真的需要 3D？（前者用 `D2.*`，后者另找引擎）
2. 时间是谁的？（**只能是调用方的**；元件里不许出现 `t` 的持有者）
